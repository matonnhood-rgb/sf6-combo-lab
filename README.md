# Combo Lab

Combo Labは、Street Fighter 6のコンボ、セットプレイ、検証メモを
日本語で整理するWindows向けアプリです。

ゲーム名は画面へ表示せず、内部では常に `Street Fighter 6` として扱います。

## 動作環境

- Windows 10 / 11
- .NET 8 Desktop Runtime

## 起動方法

`ComboLabを起動.bat` をダブルクリックしてください。
必要なビルドを行ったあと、アプリが起動します。

開発環境では次のコマンドでも起動できます。

```powershell
dotnet run
```

## 基本的な使い方

1. `アクション編集` タブで、必要な入力イベント列を登録します。
2. `コンボ編集` タブでコンボを新規登録します。
3. コンボ名、ダメージ、タグ、メモを入力します。
4. コンボタイムラインへノードを追加します。
5. `名前を付けて保存` を押してファイルへ保存します。

## 保存と読み込み

JSONファイルは、Combo Labの実行ファイルと同じ場所に作られる
`Data`フォルダー内へ保存します。

- `上書き保存`: 現在開いているJSONファイルへ保存
- `名前を付けて保存`: `Data`フォルダー内へ別名で保存
- `JSONを開く`: `Data`フォルダー内のJSONファイルを読み込み

まだ保存先が決まっていない状態で`上書き保存`を押した場合は、
名前を付けて保存する画面を表示します。

最後に開いた、または保存したJSONファイル名は`Data\last-opened.txt`へ記録します。
次回起動時は、そのJSONを自動で読み込むため、毎回`JSONを開く`必要はありません。

記録されたJSONが見つからない場合は、`Data`フォルダー内で最後に更新された
JSONを自動で読み込みます。`Data`内にJSONがない場合は空の状態で起動します。

## コンボタイムライン

コンボタイムラインは「何F目にどのアクションを使うか」を管理します。
通常の待機Fは保存せず、待ち時間は前後の入力Fの差から求めます。

アクション名は登録済みのアクション定義から選択できますが、自由入力もできます。
未登録の名前は警告表示されるだけで、そのまま保存できます。

コンボタイムラインには次の3種類のノードがあります。

### アクション

- 入力F
- アクション名

指定したフレームで使うアクションを表します。

### メモ

- 入力F
- メモ本文

検証上の注意点や補足を表します。将来実行機能を追加した場合も、
メモノードは実行対象から除外できる構造です。

### コンボ呼び出し

- 入力F
- 呼び出すコンボID
- 表示用のコンボ名

既存コンボを0F開始の部品として呼び出します。たとえば10Fで別コンボを呼び出し、
参照先のアクションが3Fなら、展開後は13Fとして扱います。

自己参照や、参照をたどって元のコンボへ戻るループ参照は追加できません。

## アクション定義

アクション定義は「アクション名に対応する、名前付きの入力イベント列」です。
技や操作の短い単位だけでなく、長い入力シーケンスや再利用する共通パーツも
保存できます。

短いアクションの例:

- 2中P
- 214中P
- SA2
- 前ステ

長いアクションの例:

- 実際にゲーム中で入力したコンボの生入力
- 成功した入力シーケンス
- 共通パーツ
- SA2追撃パーツ
- 端限定の入力パーツ

各アクション定義は次の情報を持ちます。

- ID
- アクション名
- 説明
- 入力イベント

入力イベントは、フレームと論理入力の一覧を持ちます。
画面では論理入力を `左, 中P` のようなカンマ区切りで編集します。

```text
0F: 下
2F: 左下
4F: 左, 中P
7F: ニュートラル
```

### 1P側基準

アクション定義は、基本的に1P側、つまり自キャラが右を向いている前提で作成します。

アクション定義そのものには左右反転設定を持たせません。また、現時点では
自動入力や実行機能がないため、保存した入力の左右反転は実際には行いません。

将来自動入力を実装する場合、1P側・2P側、または右向き・左向きの扱いは、
コンボタイムライン上のノード設定か実行時設定として扱う予定です。

### 複合方向

`左下`、`右下`、`左上`、`右上` は、画面上で入力しやすい論理入力として
そのまま保存できます。将来実行する場合は、内部処理で次の方向の組み合わせへ
分解できる設計です。

- 左下 = 左 + 下
- 右下 = 右 + 下
- 左上 = 左 + 上
- 右上 = 右 + 上

### 将来の入力記録

将来は、ゲーム中で実際にコンボを入力した際のキー入力やコントローラー入力を
記録し、Combo Labへ保存できる形へ拡張することを想定しています。

記録した入力は、生入力として保存したり、必要に応じてアクション定義へ変換したり、
後から人間が読みやすい名前を付けたり、共通パーツとして他のコンボから
利用したりできる構成を目指します。

入力記録機能は現在未実装です。

## アクション定義のテスト再生

アクション編集画面の `テスト再生` を押すと、選択中アクション定義の
入力イベントだけをWindowsのキー入力として送信します。コンボタイムライン全体は
再生しません。

### 入力イベントと保持時間

再生モードの選択はありません。入力イベントはすべて
「そのFで押したいキー集合」として扱います。保持時間は
`1F`、`2F`、`3F`、`5F`、`ms指定`から選べ、既定値は1Fです。

アプリは再生前に、各入力イベントのKeyDownと保持終了時点のKeyUpを展開し、
送信予定表を作ります。同じFに同じキーのKeyUpとKeyDownが重なる場合は、
不要な離し直しをせずKeepとして維持します。

```text
入力イベント:
10F: 4
11F: 4, 3

保持時間1Fで生成される予定:
10F: Down 4
11F: Keep 4 / Down 3
12F: Up 4, 3
```

同じFで実際に必要なKeyUpとKeyDownは、1つの`INPUT`配列にまとめ、
1回の`SendInput`で送信します。キーごとの待機処理は行いません。

1Fは60fps基準の約16.666ミリ秒です。送信予定表をすべて作成したあと、
高優先度の専用再生スレッドで、`Stopwatch`による再生開始からの絶対経過時間に
合わせてF順に処理します。同一Fの`INPUT`には同じWindows時刻を設定し、
API呼び出し内での時刻差が出にくい形で送信します。

### 送信方式

- `ScanCode方式`: `KEYEVENTF_SCANCODE`を使用してスキャンコードを送信
- `VirtualKey方式`: Windowsの仮想キーコードを送信

既定は`ScanCode方式`です。Street Fighter 6ではScanCode方式を推奨します。
VirtualKey方式はメモ帳など通常のWindowsアプリでの確認向けです。

### 開始待機と安全処理

開始待機は `0秒`、`1秒`、`2秒`、`3秒`、`5秒`から選べ、既定は3秒です。
待機中は `あと○秒で再生します。対象ウィンドウを前面にしてください。` と表示します。
カウントダウン終了時点で前面にあるウィンドウへ入力を送信します。

待機中と再生中は二重実行できません。`キャンセル`を押すと再生を中止します。
再生終了、キャンセル、例外、アプリ終了の際は、再生中に使用したキーをすべて
KeyUpする処理を行います。

### 再生ログ

画面には直近の入力イベント、生成した送信予定表、実際の送信結果を表示します。
詳細ログは実行ファイルと同じ場所の`logs`フォルダーへ保存します。
ログにはアクション名、送信方式、保持時間、開始待機時間、入力イベント、
KeyUp・KeyDown・Keepを整理した予定表、SendInputの送信結果、
目標送信時刻・実送信時刻・遅延量、エラーとスタックトレースを記録します。

現在、物理キー名として次のような入力を使用できます。

- `A`～`Z`
- `0`～`9`
- `Space`
- `Enter`
- `Tab`
- `Escape`
- `Backspace`
- `Delete`
- `Insert`
- `Home`
- `End`
- `PageUp`
- `PageDown`
- `Up`
- `Down`
- `Left`
- `Right`
- `Shift`
- `Ctrl`
- `Alt`
- `F1`～`F24`

ScanCode方式では、`A`、`S`、`D`、`W`、`J`、`K`、`L`、`Space`、
`Enter`、`Esc`、`Up`、`Down`、`Left`、`Right`などをスキャンコードへ
変換して送信します。KeyDownとKeyUpの両方で同じ送信方式を使用します。

`ニュートラル`、`Neutral`、`なし`、`None`、空欄は何も送信しません。
`下`や`中P`などのゲーム用論理入力から物理キーへの正式な割り当ては未実装です。

複数キーは `A, B` のようにカンマ区切りで指定できます。再生終了時には、
再生中に押したキーを念のためすべて解放します。

この機能はローカル検証やトレーニングモードでの確認用です。
オンライン対戦での使用は想定していません。

PresentMonを使ったPresent同期再生については
`docs/present-sync.md` を参照してください。

## タグ

タグはコンボ詳細画面から自由に追加・削除できます。
タグを付けずに登録することもできます。

タグは各コンボの `tags` 配列として保存します。

## 共有文

`共有文をコピー` を押すと、DiscordやXへ貼り付けやすい日本語形式で
クリップボードへコピーします。

コンボ呼び出しノードは参照先を展開して表示します。参照先の入力Fには
呼び出しノードの入力Fが加算されます。参照切れやループを検出した場合は、
無限展開せず注記を表示します。

```text
【コンボ名】画面端追撃
【ダメージ】5200
【タグ】画面端 / SA3
【入力タイムライン】
- [0F] 2中P
- [8F] コンボ呼び出し: SA3締め
  - [8F] 214中P
  - [20F] 236236強P
- [25F] メモ: 最速入力
```

## JSON保存形式

現在の保存形式は `schemaVersion: 7` です。

```json
{
  "schemaVersion": 7,
  "combos": [
    {
      "id": "33333333-3333-3333-3333-333333333333",
      "gameName": "Street Fighter 6",
      "comboName": "画面端追撃",
      "damage": 5200,
      "tags": [
        "画面端",
        "SA3"
      ],
      "notes": "検証メモ",
      "steps": [
        {
          "nodeType": "Action",
          "inputFrame": 0,
          "actionName": "2中P",
          "memoText": "",
          "calledComboId": null,
          "calledComboName": ""
        }
      ]
    }
  ],
  "actionDefinitions": [
    {
      "id": "55555555-5555-5555-5555-555555555555",
      "actionName": "214中P",
      "description": "1P側基準の入力",
      "inputEvents": [
        {
          "frame": 0,
          "logicalInputs": [
            "下"
          ]
        },
        {
          "frame": 2,
          "logicalInputs": [
            "左下"
          ]
        },
        {
          "frame": 4,
          "logicalInputs": [
            "左",
            "中P"
          ]
        }
      ]
    }
  ]
}
```

旧形式のJSONも可能な範囲で読み込めます。

- 旧 `tags` がカンマ区切り文字列の場合は配列へ変換
- 旧固定分類や旧フォルダー名はタグへ変換
- 旧入力ステップはアクションまたはメモノードへ変換
- 旧アクション行の個別メモは同じ入力Fのメモノードへ分離
- 旧 `waitFrames` は累積して `inputFrame` へ変換
- `actionDefinitions` がない旧JSONは、アクション定義が空の状態で読み込み
- アクション定義に旧 `mirrorMode` がある場合は無視し、再保存時には出力しない

## 正式な入力表記とキーマップ

アクション定義の入力イベントでは、格闘ゲーム向けの短縮表記を使えます。
方向はテンキー表記の `1` から `9`、攻撃は `lp` / `mp` / `hp` / `lk` /
`mk` / `hk` です。

```text
2
6
mp
2mp
6hk
2, mp
5lp
key:I
key:Space
```

大文字小文字は区別せず、`MP` や `2MP` は `mp` / `2mp` として扱います。
`236mp` のように複数フレームにまたがるコンボ表記は、入力イベント1行では
使えません。`0F: 2`、`2F: 3`、`4F: 6mp` のようにフレームごとへ分けて
入力してください。

キーマップは `Data/keymaps.json` に保存されます。保存対象は `2/4/6/8` と
`lp/mp/hp/lk/mk/hk` のみです。斜め方向は保存せず、次のように自動生成します。

```text
1 = 4 + 2
3 = 6 + 2
7 = 4 + 8
9 = 6 + 8
5 = ニュートラル（物理キーなし）
```

物理キーを直接指定したい場合だけ、`key:I` や `key:6` のように `key:` を
付けてください。通常の `6` は物理キーの6ではなく、右方向として解釈されます。
